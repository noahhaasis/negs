## What already exists

On the branch: the engine policy (set DIR gammas and halation baselines beat the stock
presets), the translator and helper commands, the macOS app, and on Linux:
`d45fb65` (film change nulls `STOCK_PRESET_PATHS`, session schema 2 and migration, saved
nulls survive `merge`) and `d0c3f08` (Reset Adjustments on Ctrl+Shift+R, counterclockwise
on Ctrl+Alt+R). Both were built and tested on this machine.

Helper protocol (the catalog reports `capabilities.presets`):

- `{"command": "preset_import", "text": <file contents>, "params": <current runtime params>}`
  → `{"film", "paper", "params"}`: complete runtime params, with the excluded settings
  (`presets::KEPT`: Image Size, upscale, rotation, crop, input/output encoding, speed and
  memory settings, CAT16, Post) copied from the `params` you sent. Without `params`, it only
  checks a file (for listing). Errors are user-facing reasons.
- `{"command": "preset_export", "film", "paper", "params"}` → `{"text"}`, the file to write.

Imported development times are already snapped to the stock's listed times (unset for
colour stocks), so they match a dropdown entry exactly.

## What to build

**Storage** (a Rust module, e.g. `linux/src/presets.rs`), same rules as macOS:

- Folder: `$XDG_DATA_HOME/negs/presets` (`glib::user_data_dir()`), or
  `$NEGS_PROFILE_DIR/presets` when that is set, like the session.
- Names: refuse empty, control characters, `/ \ : * ? " < > |`, a leading period or space,
  a trailing period or space, Windows device names (`CON`, `PRN`, `AUX`, `NUL`,
  `COM1`–`COM9`, `LPT1`–`LPT9`, also with an extension), more than 120 characters.
  Compare by key: NFC and case-folded (`unicode-normalization` crate or equivalent;
  check `linux/Cargo.toml` and keep `--locked` builds working). A clash gets " 2", " 3"…
- Writes never replace: write a hidden temporary file in the folder, `std::fs::hard_link`
  it to the final name (fails if it exists → next suffix), remove the temporary. Rename
  with `renameat2(RENAME_NOREPLACE)` (or link + unlink); a rename to another case of the
  same name is a plain rename. Before rename and delete, check that the file's size and
  modification time still match the listing (fresh `metadata`, nothing cached).
- Order: `.order.json` in the folder, `{"order": ["<name>.json", …]}`, the format macOS
  writes. Listed order: names in the file first, then the rest in name-key order. Adding
  appends; renaming keeps the place; deleting removes the entry; dragging rewrites it.
  Hidden files and non-`.json` files aren't presets.
- Listing re-reads the folder whenever the panel opens; cache each file's helper
  verdict by path, size and mtime.

**Applying, through the adapter.** Linux keeps controls apart from params
(`State.values`, `State.choices`, `State.params`) and rebuilds params with
`parameters::runtime`. Send `parameters::runtime(&state)` as `params`, then write the
result back through all three: control-backed paths into `values`/`choices` (the
development-time dropdown as the index of the listed time), everything else into
`params`. Set film and paper directly, **without** the film handler's side effects
(it nulls `STOCK_PRESET_PATHS`, which would discard the preset's values). One undo
step, labelled with the preset's name. The invariant to test:
`parameters::runtime(&applied_state) == result.params`.

**UI** (GTK 4 / libadwaita), as macOS behaves now:

- A header-bar toggle beside the Adjustments toggle; the sidebar becomes a `gtk::Stack`
  with an Adjustments page and a Presets page. The two are exclusive: pressing the
  other toggle switches pages, pressing the active one hides the sidebar. Remember the
  page across launches (`preferences.rs`).
- The Presets page has a header with "+" (New Preset) and a "…" menu (Import Presets…,
  Show Presets Folder), then a `ListBox` of rows: name, and the film → paper (or
  "film scan") as subtitle. Files the helper refuses are greyed, with the reason as
  subtitle and tooltip, and can still be deleted. If the folder is empty, show an empty
  state with an Import button.
- Clicking a row applies it; double-click or Enter applies it again. The row's
  context menu: Apply, Rename, Export…, Delete…. Delete asks first (`adw::AlertDialog`).
- New Preset (Ctrl+Shift+S) saves the current film, paper and Lab settings through
  `preset_export`, names the file after the film, adds it at the **bottom**, scrolls to
  it and starts renaming it inline. **Escape removes that new preset**; Enter or
  leaving the field keeps it. Escape on an existing preset only stops renaming. An
  invalid name keeps the old name and says why.
- Drag rows to reorder (`DragSource`/`DropTarget` on rows); save the order at once.
- Import Presets… (Ctrl+Shift+O, `gtk::FileDialog`, several files, `.json` and text):
  check each through `preset_import` (no `params`), copy the original bytes, list
  failures with their reasons in one dialog. Files dropped on the page
  (`gdk::FileList`) import too; dropped between rows, they go there.
- Export… copies the file byte for byte to where the user picks.
- Show Presets Folder: create it, then `gio::AppInfo::launch_default_for_uri`.
- Shortcuts: F8 shows/hides presets, Ctrl+Shift+S, Ctrl+Shift+O. All three are free in
  the app and in this machine's Hyprland bindings (its S, O and P bindings all use
  Super). Add them to the Keyboard Shortcuts dialog.
- Linux has no data-cleanup command, so there is no cleanup text to change.

## Building on this machine

`bash linux/build.sh` and `bash linux/run.sh` from the worktree (see linux-app.md). The
pinned toolchain and the development OpenBLAS sysroot live in
`~/Work/Negs/target/linux-toolchain`. If a worktree's `linux/core-env.sh` can't find the
sysroot, point it at the clone's: `RUSTUP_HOME` and `CARGO_HOME` under that folder,
`PKG_CONFIG_PATH=~/Work/Negs/target/linux-toolchain/sysroot/pkgconfig` and
`LD_LIBRARY_PATH=~/Work/Negs/target/linux-toolchain/sysroot/usr/lib`. Don't let
`core-env.sh` rewrite the clone's `openblas.pc` for another root.
