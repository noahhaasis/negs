`schema_1_drops_dir_and_halation_values_that_never_applied`, and fix anything they show.

Helper protocol (the catalog reports `capabilities.presets`):

- `{"command": "preset_import", "text": <file contents>, "params": <current params>}` →
  `{"film", "paper", "params"}`: complete params, with the excluded settings
  (`presets::KEPT`: Image Size, upscale, rotation, crop, input/output encoding, speed and
  memory settings, CAT16, Post) copied from the `params` you sent. Without `params`, it only
  checks a file (for listing). Errors are user-facing reasons.
- `{"command": "preset_export", "film", "paper", "params"}` → `{"text"}`, the file to write.

Imported development times are already snapped to the stock's listed times (unset for
colour stocks), so they match a drop-down entry exactly.

## What to build

**Storage** (e.g. `windows/src/presets.rs`), same rules as macOS:

- Folder: `%APPDATA%\Negs\Presets` (`session::settings_dir().join("Presets")`, so
  `NEGS_PROFILE_DIR` moves it too).
- Names: refuse empty, control characters, `/ \ : * ? " < > |`, a leading period or space,
  a trailing period or space, Windows device names (`CON`, `PRN`, `AUX`, `NUL`,
  `COM1`–`COM9`, `LPT1`–`LPT9`, also with an extension), more than 120 characters.
  Compare by key: NFC and case-folded (NTFS doesn't normalize, so the key matters here
  too). A clash gets " 2", " 3"…
- Writes never replace: write a hidden temporary file in the folder,
  `std::fs::hard_link` it to the final name (fails if it exists → next suffix), remove the
  temporary. `std::fs::rename` replaces on Windows: rename with `MoveFileExW` **without**
  `MOVEFILE_REPLACE_EXISTING`; another case of the same name is the same file there, so a
  case-only rename must still work. Before rename and delete, check that the file's size and
  modification time still match the listing (fresh metadata). Mind sharing violations
  (Explorer previewing the file): report them, never retry silently into a different file.
- Order: `.order.json` in the folder, `{"order": ["<name>.json", …]}`, the format macOS
  writes. Listed order: names in the file first, then the rest in name-key order. Adding
  appends; renaming keeps the place; deleting removes the entry; dragging rewrites it.
  Hidden files (leading period, or the hidden attribute) and non-`.json` files aren't presets.
- Listing re-reads the folder whenever the panel opens; cache each file's helper verdict
  by path, size and modification time.

**Applying.** Send the state's params as `params`, then replace them with the result and
set film and paper directly, **without** `choose_film`'s side effects (it nulls the stock
preset fields and would discard the preset's values). One undo step named
`Apply Preset “<name>”`. The preview limit and anything outside params stay.

**UI** (Win32 and the standard common controls, light mode), as macOS behaves now:

- A toolbar button "Presets" beside Adjustments, with the checked state; the adjustments
  column shows either the adjustments or the presets panel. The two are exclusive:
  pressing the other button switches panels, pressing the checked one hides the column.
  Remember the panel across launches (with the other preferences in `session.rs`).
- Menus: View ▸ Presets (F8, beside Adjustments F7), File ▸ New Preset (Ctrl+Shift+S) and
  Import Presets… (Ctrl+Shift+O). All three keys are unused in `accelerators()` today.
- The panel: a header with "+" (New Preset) and a "…" menu button (Import Presets…, Show
  Presets Folder), then a ListView in report view (`LVS_EDITLABELS`) with the name and a
  second line or column for the film → paper ("film scan" when scanned). Files the helper
  refuses are greyed, with the reason as the subtitle and tooltip, and can still be
  deleted. If the folder is empty, show an empty state with an Import button.
- Clicking a row applies it; double-click or Enter applies it again. The row's context
  menu: Apply, Rename, Export…, Delete…. F2 renames (label edit). Delete asks first
  (`TaskDialog`).
- New Preset saves the current film, paper and Lab settings through `preset_export`, names
  the file after the film, adds it at the **bottom**, scrolls to it and starts the label
  edit. **Escape removes that new preset**; Enter or leaving the edit keeps it. Escape on an
  existing preset only cancels the rename. An invalid name keeps the old name and says why.
- Drag rows to reorder (ListView drag with an insertion mark, `LVM_SETINSERTMARK`) and save
  the order at once. Dragging must not apply the preset.
- Import Presets… (`IFileOpenDialog`, several files, `.json` and text): check each through
  `preset_import` (no `params`), copy the original bytes, list failures with their reasons
  in one dialog. Files dropped on the panel import too (extend the OLE drop target in
  `ui/drop.rs`, which today takes one photograph); dropped between rows, they go there.
- Export… copies the file byte for byte (`IFileSaveDialog`).
- Show Presets Folder: create it, then open it in Explorer (`ShellExecuteW` "open" or
  `SHOpenFolderAndSelectItems`).
- Launch speed is a hard requirement: create the panel lazily on first show, and don't
  list or check presets at startup unless the panel is the remembered one. Measure with
  `windows/measure_startup.ps1` before and after.

**Uninstaller** (`installer.iss`): "Remove all app data" also deletes the Presets folder
